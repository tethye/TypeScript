## 1️⃣ Introduction to Interfaces

Before interfaces, most TypeScript features like modules and classes already existed in JavaScript (especially modern ES6+ JavaScript). However, **interfaces are a feature introduced by TypeScript**.

JavaScript does not have built-in interfaces. TypeScript adds them to help developers write **safer, more predictable code.**

### 🔎 What Is an Interface?

An interface is a **contract that defines the structure an object must follow.**

If something implements or uses an interface, it guarantees that it **contains certain properties or methods.**

## 2️⃣ The Basics About Interfaces
**❌ Problem Without Interface**

```ts
function greet(person: any) {
  console.log("Hello " + person.name);
}

const person = {
  firstName: "Max",
  age: 27
};

greet(person); // Hello undefined
```
There is no error at compile time. The mistake is detected only at runtime.

**✅ Solution With Type Definition**
```ts
function greet(person: { name: string }) {
  console.log("Hello " + person.name);
}
```
Now TypeScript ensures the object has a name property.

**✅ Better Solution: Using an Interface**
```ts
interface NamedPerson {
  name: string;
}

function greet(person: NamedPerson) {
  console.log("Hello " + person.name);
}
```
Now the structure is **reusable and cleaner.**

## 3️⃣ Interfaces and Properties
**Required Properties**
```ts
interface NamedPerson {
  firstName: string;
}

const person: NamedPerson = {
  firstName: "Max"
};
```
If firstName is *missing → compile error.*

**Optional Properties**
```ts
interface NamedPerson {
  firstName: string;
  age?: number;
}
```
The **?** makes a property optional.
```ts
const person: NamedPerson = {
  firstName: "Max"
}; // Valid
```
**⚠️ Special Case: Object Literal Check**

This works:
```ts
const person = {
  firstName: "Max",
  age: 27
};

greet(person);
```

**But this causes error:**
```ts
greet({
  firstName: "Max",
  age: 27
});
```
***Why?***

TypeScript performs **strict object literal checking when passing directly**.

## 4️⃣ Dynamic / Flexible Properties (Index Signatures)

**When property names are unknown:**

```ts
interface NamedPerson {
  firstName: string;
  [propName: string]: any;
}
```
Example:
```ts
const person: NamedPerson = {
  firstName: "Max",
  hobbies: ["Cooking", "Sports"],
  isMarried: false
};
```
This allows **flexible additional properties**.

## 5️⃣ Interfaces and Methods

Interfaces can also define methods.

```ts
interface NamedPerson {
  firstName: string;
  greet(lastName: string): void;
}
```
Implementation:
```ts
const person: NamedPerson = {
  firstName: "Max",
  greet(lastName: string) {
    console.log("Hi, I am " + this.firstName + " " + lastName);
  }
};
person.greet("Smith");
```

## 6️⃣ Using Interfaces with Classes

Classes can implement interfaces using the **implements** keyword.
**Example 1:**
```ts
interface NamedPerson {
  firstName: string;
  greet(lastName: string): void;
}

class Person implements NamedPerson {
  firstName: string;

  greet(lastName: string) {
    console.log("Hi, I am " + this.firstName + " " + lastName);
  }
}
```
Usage:
```ts
const myPerson = new Person();
myPerson.firstName = "Max";
myPerson.greet("Smith");
```
**Example 2:**
```ts

interface User{
    name : string;
    [prop : string]: unknown;
    foo(...args): void;
}
class userObj implements User  {
    name = "Tethye";
    [prop : string]: unknown;
    foo(...args){
        write(...args);
    }
}    

const obj = new userObj();
obj.age = 27;
obj.role = 'Super';
obj.foo(obj.age, obj.role);
```

🔹 Important Points

A class must implement all required properties and methods

Optional properties are not required

A class may have additional properties not defined in the interface

7️⃣ Interfaces for Function Types

Interfaces can describe function shapes.

interface DoubleValueFunc {
  (num1: number, num2: number): number;
}

Implementation:

let myDoubleFunction: DoubleValueFunc;

myDoubleFunction = function(value1: number, value2: number) {
  return (value1 + value2) * 2;
};

console.log(myDoubleFunction(10, 20)); // 60

If return type or parameters mismatch → compile error.

8️⃣ Interface Inheritance (Extending Interfaces)

Interfaces can extend other interfaces.

interface NamedPerson {
  firstName: string;
  greet(lastName: string): void;
  age?: number;
}

interface AgedPerson extends NamedPerson {
  age: number; // Now required
}

Example:

const oldPerson: AgedPerson = {
  firstName: "Max",
  age: 60,
  greet(lastName: string) {
    console.log("Hello " + lastName);
  }
};
🔹 Key Concepts

Child interface inherits all properties

Can add new properties

Can override optional → required

9️⃣ What Happens After Compilation?

When TypeScript compiles to JavaScript:

➡️ Interfaces completely disappear

Example:

TypeScript:

interface NamedPerson {
  firstName: string;
}

Compiled JavaScript:

// Nothing related to interface
Why?

JavaScript does not support types or interfaces.
Interfaces exist only during development to:

Catch errors early

Improve IntelliSense

Enforce structure

🔟 Additional Important Concepts (Missing but Important)
1. Readonly Properties
interface NamedPerson {
  readonly id: number;
  firstName: string;
}

Once assigned, id cannot be changed.

2. Interface vs Type Alias

Both can define object shapes:

type Person = {
  firstName: string;
};

But interfaces:

Can be extended

Can be merged (declaration merging)

3. Multiple Interface Inheritance
interface A {
  name: string;
}

interface B {
  age: number;
}

interface C extends A, B {
  role: string;
}
4. Implementing Multiple Interfaces
class Employee implements A, B {
  name: string;
  age: number;
}
5. Interface Declaration Merging (Advanced Feature)
interface Person {
  name: string;
}

interface Person {
  age: number;
}

Result:

interface Person {
  name: string;
  age: number;
}

TypeScript merges them automatically.
