## 📌 Introduction

As JavaScript applications grow, managing code in a single file quickly becomes messy. In the past, developers used various module loaders to split large projects into multiple files.

**TypeScript** provides two powerful concepts for organizing code:

* Namespaces

* Modules

Both allow you to structure applications, but they serve different purposes and are suited to different project sizes.

In this guide, you’ll learn:

* What namespaces are

* What modules are

* How both work

* How to use them across multiple files

* When to choose one over the other

Their advantages and limitations

## 1️⃣ Namespaces
### What Is a Namespace?

A **namespace** groups related code together under a single name. It prevents global scope pollution by wrapping related variables and functions inside a container.

***Think of it like a JavaScript object that organizes code logically.***

### Why Use Namespaces?

**Without namespaces:**
```ts
const pi = 3.14;

function calculateCircumference(diameter: number) {
  return diameter * pi;
}

function calculateRectangle(width: number, length: number) {
  return width * length;
}
```
**Problems:**

* Everything lives in the global scope

* Risk of naming conflicts

* Difficult to manage large codebases

**Creating a Namespace**

```ts
namespace MyMath {
  const pi = 3.14;

  export function calculateCircumference(diameter: number) {
    return diameter * pi;
  }

  export function calculateRectangle(width: number, length: number) {
    return width * length;
  }
}
```
**Important:** *export*

*Only exported members are accessible outside the namespace.*

**Using a Namespace**
```ts
console.log(MyMath.calculateRectangle(10, 20));
console.log(MyMath.calculateCircumference(10));
```

**Output:**
```
200
31.4
```

Namespaces Prevent Global Pollution

This works without conflict:

const pi = 2.99; // Global scope

console.log(pi); // 2.99

Because:

MyMath.pi // ❌ Not accessible (not exported)

Namespaces isolate code.

2️⃣ Namespaces Across Multiple Files

Large projects need multiple files.

Example Structure
app.ts
circle-math.ts
rectangle-math.ts
circle-math.ts
namespace MyMath {
  const pi = 3.14;

  export function calculateCircumference(diameter: number) {
    return diameter * pi;
  }
}
rectangle-math.ts
namespace MyMath {
  export function calculateRectangle(width: number, length: number) {
    return width * length;
  }
}
app.ts
/// <reference path="circle-math.ts" />
/// <reference path="rectangle-math.ts" />

console.log(MyMath.calculateRectangle(10, 20));
console.log(MyMath.calculateCircumference(10));
Bundling Files Together

Use the TypeScript compiler:

tsc --outFile app.js app.ts

This combines all referenced files into one JavaScript file.

⚠️ Important: Order Matters

Namespaces rely on:

File ordering

Manual dependency management

If order is wrong → errors occur.

3️⃣ Nested Namespaces

You can nest namespaces:

namespace MyMath {
  export namespace Circle {
    const pi = 3.14;

    export function calculateCircumference(diameter: number) {
      return diameter * pi;
    }
  }
}

Usage:

console.log(MyMath.Circle.calculateCircumference(10));
Creating Aliases
import CircleMath = MyMath.Circle;

console.log(CircleMath.calculateCircumference(10));

This improves readability.

4️⃣ Limitations of Namespaces

Namespaces have drawbacks:

❌ Not fully declarative

❌ Dependency tracking is manual

❌ File order must be maintained

❌ Hard to scale in large projects

They are suitable for:

Small projects

Internal libraries

Simple browser-based scripts

For larger applications → Modules are better

5️⃣ Modules

Modules are the modern way to structure TypeScript applications.

They:

Have their own scope

Explicitly declare dependencies

Require a module loader (or bundler)

Scale better

Example Folder Structure
math/
  circle.ts
  rectangle.ts
app.ts
circle.ts
export const pi = 3.14;

export function calculateCircumference(diameter: number) {
  return diameter * pi;
}
rectangle.ts
export function calculateRectangle(width: number, length: number) {
  return width * length;
}
Importing in app.ts
import { pi, calculateCircumference } from "./math/circle";
import { calculateRectangle } from "./math/rectangle";

console.log(pi);
console.log(calculateCircumference(10));
console.log(calculateRectangle(20, 50));
6️⃣ Why Modules Need a Loader

JavaScript originally didn’t support:

import ...
export ...

TypeScript compiles this into module formats like:

CommonJS (require)

AMD (define)

ES Modules

Browsers need help understanding them.

Example Module Formats
CommonJS (used in Node.js)
const circle = require("./math/circle");
AMD
define(["./math/circle"], function(circle) {});

Browsers don’t understand these by default.

7️⃣ Using a Module Loader

A module loader allows browsers to understand modules.

Example: SystemJS

Installation
npm install systemjs --save
index.html Setup
<script src="node_modules/systemjs/dist/system.js"></script>

<script>
  System.config({
    baseURL: '/',
    defaultJSExtensions: true
  });

  System.import('app.js');
</script>

Now modules work in the browser.

8️⃣ Import & Export Variations
1️⃣ Named Exports
export function calculateRectangle() {}

Import:

import { calculateRectangle } from "./math/rectangle";
2️⃣ Import Everything
import * as Circle from "./math/circle";

console.log(Circle.pi);
3️⃣ Default Export

rectangle.ts:

export default function calculateRectangle(width: number, length: number) {
  return width * length;
}

Import:

import calc from "./math/rectangle";

The name calc can be anything.

9️⃣ Module Resolution

TypeScript resolves:

.ts

.tsx

.d.ts

Automatically.

Relative Import
import { something } from "./file";
Absolute Import
import { Component } from "@angular/core";

Absolute imports are resolved from node_modules.

🔟 Namespaces vs Modules
Feature	Namespaces	Modules
Scope	Global container	Own file scope
Dependency Management	Manual	Explicit
Scales well?	❌ Not ideal	✅ Yes
Requires loader?	❌ (if bundled)	✅ Yes
Recommended for	Small apps	Medium & large apps
When To Use What?
Use Namespaces When:

Small browser-only project

No build tools

Simple scripts

Use Modules When:

Medium or large application

Using modern tooling

Working with Node.js

Using frameworks

Need maintainability & scalability

🏁 Final Summary

You now understand:

How namespaces organize code

How modules create true file-level isolation

How to export and import functionality

Why module loaders are required

When to choose namespaces vs modules

Key Takeaway

For modern TypeScript development → Use Modules

Namespaces are useful historically and in specific cases, but modules are the scalable, maintainable solution for real-world applications.
