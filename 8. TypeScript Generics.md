# Module: Introduction to Generics

This section follows the introduction to generics, moving from the problem of using `any` to the solution provided by generic functions.

## 1. The Problem: Using `any` for Generic Logic
In the initial attempt to create a flexible "echo" function, the `any` type is used. While this allows the function to accept any data, it causes TypeScript to lose track of the specific type once the data is returned.

```ts
// A basic function that accepts any type
function echo(data: any) {
    return data;
}

// Usage examples
console.log(echo("Max").length);         // Works, but no IDE support
console.log(echo(27).length);            // Returns 'undefined' (no compiler error)
console.log(echo({name: "Max", age: 27}).length); // Returns 'undefined'
```

### Key Issues with `any`:
*   **Lack of IDE Support:** The IDE cannot provide auto-completion (e.g., for `.length`) because it doesn't know the return type.
*   **Runtime Errors:** TypeScript does not flag an error if you try to access a property (like `.length`) on a `number`, leading to `undefined` results at runtime.

---

## 2. The Solution: Creating a Generic Function
To fulfill the goal of having "flexible and yet manageable" code, a generic function uses a type variable (typically `<T>`) to capture the type of the argument provided.

```ts
// The 'better' generic way
function betterEcho<T>(data: T): T {
    return data;
}

// Usage with Type Inference
console.log(betterEcho("Max").length); // TypeScript knows this is a string

// Usage with Explicit Type Assignment
console.log(betterEcho<number>(27)); // Explicitly tells TS to use 'number'
```

### Benefits of the Generic Approach:
*   **Type Awareness:** TypeScript remains aware of the exact data type of the result. For example, if you pass a number to `betterEcho`, TypeScript will throw a compilation error if you try to access `.length`.
*   **Flexibility:** The function can still work with any data type (strings, numbers, objects) while maintaining full type safety.


# Why and What: The Need for Generics

This section demonstrates the "Why" behind generics by looking at a function that is intended to be flexible but suffers from a lack of type safety due to the use of the `any` type [1].

## 1. The Initial "Generic" Function (Using `any`)
To create a function that can handle any data type, we might initially use the `any` type. This function simply "echoes" back whatever is passed into it [1].

```typescript
// A very generic function using 'any'
function echo(data: any) {
    return data;
}

// It can accept strings, numbers, or objects
console.log(echo("Max"));                        // Output: "Max"
console.log(echo(27));                           // Output: 27
console.log(echo({ name: "Max", age: 27 }));     // Output: { name: "Max", age: 27 }
```
## 2. Identifying the Problem: Lack of Type Awareness
While this function works with multiple types, it has a major disadvantage: TypeScript loses track of the specific data type once the function returns the value.
**A. Poor IDE Support**

When using any, the IDE (Integrated Development Environment) cannot provide accurate auto-completion. For example, even if you pass a string, the IDE won't "fatly" suggest string-specific properties like .length because it doesn't know for sure that a string is being returned.
// The IDE does not offer '.length' as a suggestion here
console.log(echo("Max").length);

**B. Runtime Errors vs. Compilation Errors**
The most significant issue is that TypeScript cannot catch errors at compile time when using any. If you attempt to access a property that doesn't exist on a specific type (like .length on a number), TypeScript will allow it to compile, resulting in undefined at runtime.
// This code compiles without error despite 'number' not having a length
console.log(echo(27).length); // Result at runtime: undefined

## 3. The Goal**
The goal of using generics is to create a function that can handle all kinds of data while ensuring that TypeScript remains aware of the exact data type returned. This allows for a function to be both flexible and manageable by the compiler, providing the benefits of strong typing even in dynamic scenarios.


# Creating a Generic Function

A **generic function** is defined using a specific syntax that tells TypeScript it will operate on a type that is determined when the function is called. This allows the code to be both **flexible and strictly typed**, avoiding the pitfalls of the `any` type.


## 1. Syntax of a Generic Function
To create a generic function, you use **angle brackets** (`< >`) containing a type variable, typically an uppercase **`T`** (though any character or name can be used).

```typescript
// The generic 'T' acts as a placeholder for the type
function betterEcho<T>(data: T): T {
    return data;
}
```
In this example, the character `T` tells TypeScript: "Give me the type when using this function, and I will use that same type for the input and the return value."

---

## 2. Coding Example: Type Inference
When you call a generic function, TypeScript can often **infer** the type based on the argument you pass in.

```typescript
// TypeScript infers T as 'string'
console.log(betterEcho("Max").length); 
```
**Benefits:**
*   **IDE Support:** Because TypeScript knows the return type is a string, it provides full auto-completion for string properties like `.length`.
*   **Type Safety:** If you try to perform an operation not supported by the inferred type, the compiler will flag it.

---

## 3. Coding Example: Error Prevention
Generics prevent the runtime errors that occur when using `any`. If you pass a number to the generic function, TypeScript knows the result is a `number` and will block access to string-specific properties.

```typescript
// This will trigger a TypeScript error
console.log(betterEcho(27).length); 
```
**Compiler Error:** `Property 'length' does not exist on type 'number'`. This ensures you cannot perform operations that are unsupported by the actual data type.

---

## 4. Coding Example: Explicit Type Assignment
While TypeScript can usually infer the type, you can also **explicitly state** which type the generic function should use by including the type in angle brackets during the call.

```typescript
// Explicitly setting T to 'number'
console.log(betterEcho<number>(27)); 

// This will trigger an error because the argument does not match the explicit type
console.log(betterEcho<number>("Max")); 
```
**Compiler Error:** TypeScript will throw an error because you explicitly required a `number`, but provided a `string`.

---

## 5. Summary of Advantages
Using the syntax demonstrated in `092 Creating a Generic Function.mp4` makes your code:
*   **Dynamic:** The same function can handle many different types.
*   **Manageable:** The TypeScript compiler remains aware of the exact data types, providing better error checking and developer support than the `any` type.



# Built-in Generic Type: Arrays

The most prominent **built-in generic** in TypeScript is the **Array**. While you can define arrays using standard shorthand, they are fundamentally a generic type that can be explicitly defined to enforce strict typing.

## 1. Defining a Generic Array
Normally, you might create an array by simply assigning values, allowing TypeScript to infer the type. However, using the generic syntax `Array<type>` allows you to be explicit about what the array should contain.

```typescript
// Standard array creation (inferred)
let testResults = [1.1, 2.1];

// Explicitly defining the array as a generic type
let testResults: Array<number> = [1.1, 2.1];
```

## 2. Type Safety and Compiler Support
By explicitly setting the type of the array using generic syntax, you gain **compiler support** that prevents you from accidentally adding the wrong data type to your collection.

```typescript
// This works because 33.1 is a number
testResults.push(33.1);

// This will trigger a compiler and IDE error
// Error: Argument of type 'string' is not assignable to parameter of type 'number'
testResults.push("high"); 
```

## 3. Benefits of Explicit Generic Arrays
*   **Prevent Mixed Types:** While JavaScript allows you to mix strings, numbers, and objects in a single array, TypeScript's generic array type ensures you don't do this accidentally if you want a clean, single-type collection.
*   **Reliable Output:** Because the type is strictly enforced, you can rely on the data structure when performing operations like logging or calculations.

```typescript
// Outputting the explicitly typed number array
console.log(testResults); 
```

By using the `Array<number>` syntax, you are telling TypeScript: "This is an array, and it must **only hold numbers**". This makes your code more manageable and prevents runtime errors caused by unexpected data types within your arrays.


# Generic Types and Arrays

In this section, the focus is on how **generic types can be assigned to represent arrays** within functions. This allows you to create flexible logic that is guaranteed to operate on a collection of elements.

## 1. Defining a Function with a Generic Array
You can specify that a function argument is an array of a generic type by using the syntax **`args: T[]`**. This tells TypeScript that while the specific type of the elements (`T`) is not yet known, the input itself will definitely be an array.

```typescript
// A function that takes an array of generic type T
function printAll<T>(args: T[]) {
    // Because TypeScript knows 'args' is an array, 
    // we can use built-in array methods like forEach.
    args.forEach((element) => console.log(element));
}
```

## 2. Advantages of the `T[]` Syntax
Even though TypeScript does not know the specific type of the elements inside the array at the time the function is defined, specifying **`T[]`** provides immediate benefits:
*   **Access to Array Methods:** You can immediately use methods like **`.forEach()`**, `.map()`, or `.push()` because the compiler recognizes the argument as an array structure.
*   **Element Type Awareness:** Within the loop (like the `.forEach` arrow function), TypeScript treats each `element` as being of type `T`.

## 3. Calling the Function
When calling the function, TypeScript can either **infer** the type from the values in the array or you can **explicitly state** the type.

### Example: Type Inference
```typescript
// TypeScript infers T as 'string' based on the array contents
printAll(['apples', 'banana']); 
```

### Example: Explicit Type Assignment
You can be more explicit by providing the type within angle brackets before the function arguments.

```typescript
// Explicitly telling TypeScript T is a 'string'
printAll<string>(['apples', 'banana']);
```

This approach ensures that your code remains **flexible** enough to handle arrays of any type (strings, numbers, objects) while remaining **strictly typed** and manageable by the TypeScript compiler.


# Using Generic Types

In this section, the focus shifts from creating generic functions to assigning **generic types** to variables or constants. This allows you to define a specific function signature that uses generics before actually assigning a function to it.

## 1. Defining a Generic Function Type
You can create a constant and assign it a **generic function type**. This looks similar to a standard function type assignment but includes the generic `<T>` syntax.

```typescript
// Assignment of a generic function type to a constant
const echo2: <T>(data: T) => T = betterEcho;
```

### Breakdown of the Syntax:
*   **The Constant:** `const echo2` is the name of the variable.
*   **The Type Assignment:** Everything after the colon (`:`) but before the equal sign (`=`) is the type. It tells TypeScript that this constant must hold a function that accepts one argument of type `T` and returns a value of type `T`.
*   **The Assignment:** The equal sign (`=`) assigns an actual function (in this case, `betterEcho`) to the constant.

---

## 2. Coding Example: Reusing a Generic Function
This approach is useful for assigning existing generic logic (like the `betterEcho` function from previous lessons) to a new variable while maintaining strict typing.

```typescript
// The original generic function
function betterEcho<T>(data: T): T {
    return data;
}

// Assigning it to a constant with a generic type signature
const echo2: <T>(data: T) => T = betterEcho;

// Calling the constant just like the original function
console.log(echo2<string>("Something")); 
```

## 3. Benefits of Generic Type Assignment
*   **Explicit Contracts:** It allows you to define exactly what kind of generic function a variable is allowed to hold.
*   **Consistency:** It ensures that any function assigned to that variable follows the same input/output type rules defined by the generic.
*   **Flexibility:** You can still be **explicit about the type** when calling the constant (e.g., `echo2<string>`), giving you full IDE support and type safety.

This technique allows you to treat generic logic as a **reusable type definition**, making your TypeScript code more modular and manageable.




# Creating a Generic Class

Beyond functions and types, **generic classes** are a fundamental and frequently used construct in TypeScript. They allow you to create a class structure where the specific data types for properties or methods are defined at the time of instantiation.

## 1. The Initial Problem: A Non-Generic Class
To understand the value of a generic class, consider a basic `SimpleMath` class designed to multiply two values. Without generics, properties might be left implicitly as `any`, which can lead to runtime issues that the compiler won't catch.

```typescript
// Initial non-generic approach
class SimpleMath {
    baseValue;
    multiplyValue;

    calculate() {
        return this.baseValue * this.multiplyValue;
    }
}

const simpleMath = new SimpleMath();
simpleMath.baseValue = 10;
simpleMath.multiplyValue = "something"; // No compilation error here!
console.log(simpleMath.calculate());   // Output: NaN (Not a Number)
```
In this scenario, passing a string to a mathematical operation results in `NaN` at runtime, but TypeScript provides no warning during development.

---

## 2. Refactoring to a Generic Class
To make the class "flexible and yet manageable," you use the same syntax as generic functions by adding **angle brackets** (`<T>`) after the class name. This creates an internal type `T` that can be reused throughout the class body.

### Defining the Class with `<T>`
```typescript
class SimpleMath<T> {
    baseValue: T;
    multiplyValue: T;

    // The method is set to always return a number
    calculate(): number {
        // Casting with '+' is required here (see below)
        return +this.baseValue * +this.multiplyValue;
    }
}
```

### Key Components:
*   **Type Placeholder (`T`)**: Tells TypeScript that the user will specify a type when creating an instance of this class.
*   **Property Assignment**: Both `baseValue` and `multiplyValue` are assigned the type `T`.
*   **Arithmetic Operations**: TypeScript will flag an error if you try to multiply `T` directly because it doesn't know if `T` will be a number. To satisfy the compiler, you can **explicitly cast** the values using a `+` prefix.

---

## 3. Instantiating and Using the Generic Class
Once defined, you can create instances of the class and specify the type you want to work with.

```typescript
// Creating an instance specifically for numbers
const simpleMath = new SimpleMath<number>();

simpleMath.baseValue = 10;
simpleMath.multiplyValue = 20;

console.log(simpleMath.calculate()); // Output: 200
```

## 4. Current Limitations
In this basic generic implementation from source **096**, even though we have set the class to use `<number>`, the generic `T` is still technically "any" type the user provides unless constraints are added. 

For example, if a user tries to instantiate it as `new SimpleMath<string>()`, the code will compile, but the arithmetic will still result in `NaN`. This sets the stage for using **Constraints** (the `extends` keyword) to further restrict which types are allowed, which is covered in the following sections of the sources.

# Generic Constraints

While generic classes provide flexibility, they can sometimes be *too* flexible, allowing types that don't work with your class logic (such as passing a string to a math class). **Constraints** allow you to restrict the types that can be used with a generic by using the **`extends` keyword**.

## 1. Using a Single Type Constraint
By adding `extends number` to your generic declaration, you tell TypeScript that the type `T` must be a number or a type that inherits from number.

```typescript
// Restricting the generic to only allow numbers
class SimpleMath<T extends number> {
    baseValue: T;
    multiplyValue: T;

    calculate(): number {
        // Casting is still required because T is a generic placeholder
        return +this.baseValue * +this.multiplyValue;
    }
}

// This works because number satisfies the constraint
const simpleMath = new SimpleMath<number>();
simpleMath.baseValue = 10;
simpleMath.multiplyValue = 20;

// This will now trigger a COMPILATION ERROR
// Error: Type 'string' does not satisfy the constraint 'number'
const errorMath = new SimpleMath<number>();
errorMath.baseValue = "ten"; 
```

---

## 2. Using Multiple Type Constraints (Union Types)
You can also constrain a generic to **multiple base types** by using a union type with the `extends` keyword. This is useful if your logic can handle different specific types (like both strings and numbers).

```typescript
// Allowing T to be either a number OR a string
class SimpleMath<T extends number | string> {
    baseValue: T;
    multiplyValue: T;

    calculate(): number {
        return +this.baseValue * +this.multiplyValue;
    }
}

// This now works with strings because of the updated constraint
const stringMath = new SimpleMath<string>();
stringMath.baseValue = "10";
stringMath.multiplyValue = "20";
console.log(stringMath.calculate()); // Output: 200
```

---

## 3. Strict Validation and Unsupported Types
The power of constraints lies in **blocking unsupported types** at compile time. For example, even if a type like `boolean` could technically be cast to a number in JavaScript, you can block it using a constraint if it doesn't fit your intended logic.

```typescript
// Trying to use a boolean when the constraint only allows number | string
// COMPILATION ERROR: Type 'boolean' does not satisfy the constraint 'number | string'
const booleanMath = new SimpleMath<boolean>(); 
```

## Summary of Constraints
*   **Syntax:** Use `<T extends BaseType>`.
*   **Purpose:** It controls which values can be passed to a generic class or function, ensuring that the "flexible" code remains "manageable" and type-safe.
*   **Error Prevention:** Instead of getting `NaN` at runtime, TypeScript provides a **compilation error** as soon as an invalid type is used.

# Using More Than One Generic Type

Sometimes, a single generic type placeholder isn't enough to provide the flexibility your code requires. For instance, in a math class, you might want the base value to be a `string` and the multiplier to be a `number`. Using multiple generic types allows you to handle these types independently.

## 1. The Problem: Single Type Limitation
In a class using only one generic type (`<T>`), every property assigned that type must be the same. This prevents you from mixing data types during instantiation.

```typescript
// With one type, both values MUST be the same (e.g., both strings)
const math = new SimpleMath<string>();
math.baseValue = "10";
math.multiplyValue = 20; // This would cause an error!
```

---

## 2. Solution: Using `T` and `U`
You can define multiple generic types by separating them with commas. By convention, TypeScript developers use **alphabetical order**, starting with **`T`**, then **`U`**, then `V`, and so on.

### Defining the Class with Multiple Types
In this example, we restrict both `T` and `U` to be either `number` or `string` using constraints, but they can now be assigned independently of each other.

```typescript
class SimpleMath<T extends number | string, U extends number | string> {
    baseValue: T;
    multiplyValue: U;

    calculate(): number {
        // Explicitly casting to number with '+' to allow math on generic types
        return +this.baseValue * +this.multiplyValue;
    }
}
```

---

## 3. Instantiating with Different Types
When you create an instance of the class, you can now specify a different type for each generic placeholder.

```typescript
// T is set to 'string', U is set to 'number'
const mixedMath = new SimpleMath<string, number>();

mixedMath.baseValue = "10";   // Valid because T is string
mixedMath.multiplyValue = 20;  // Valid because U is number

console.log(mixedMath.calculate()); // Output: 200
```

---

## 4. Important Note on Constraints
The source emphasizes that while you can make one type extend another (e.g., `T extends U`), this forces `T` to be the **same type** as `U`. To maintain the ability to mix different types, you should provide individual constraints for each, such as:
*   `T extends number | string`
*   `U extends number | string`

This setup ensures the class is "flexible and yet manageable," allowing for various combinations of valid types while still catching invalid ones (like `boolean`) at compile time.

# Module Exercise Solution: Creating a Generic Map Class

The goal of this exercise was to create a **reusable, generic map class** that functions as a collection object for storing key-value pairs, similar to a standard JavaScript object.

## 1. Defining the Generic Class Structure
The class, named `MyMap`, is defined as a **generic class** without constraints, allowing it to hold any type `T`. It uses a **private property** called `map` for internal storage.

```typescript
class MyMap<T> {
    // Internal storage: an object where keys are strings and values are of type T
    private map: { [key: string]: T } = {}; 
}
```
*   **Key-Value Pair Logic:** The internal map is defined such that every key is a **string**, and every value corresponds to the generic type **`T`** provided during instantiation.

---

## 2. Implementing Class Methods
The class includes four core methods to manage the data.

### `setItem(key: string, item: T)`
This method adds a new key-value pair to the map.
*   **Overwriting Behavior:** If a key already exists, the method is designed to **overwrite** the existing value, ensuring each key appears only once in the map.

```typescript
setItem(key: string, item: T) {
    this.map[key] = item;
}
```

### `getItem(key: string)`
This method retrieves the value associated with a specific string key.

```typescript
getItem(key: string) {
    return this.map[key];
}
```

### `clear()`
The `clear` method resets the internal storage by setting the map back to an **empty object**.

```typescript
clear() {
    this.map = {};
}
```

### `printMap()`
This method uses a **`for...in` loop** to iterate through all keys in the private map property and log them along with their values to the console.

```typescript
printMap() {
    for (const key in this.map) {
        console.log(key, this.map[key]);
    }
}
```

---

## 3. Usage Example: Number Map
You can instantiate the class specifically for **numbers**, ensuring that only numeric values can be stored.

```typescript
const numberMap = new MyMap<number>();

numberMap.setItem("apples", 10);
numberMap.setItem("bananas", 2);

console.log(numberMap.getItem("apples")); // Output: 10
numberMap.printMap();                     // Output: apples 10, bananas 2
numberMap.clear();
numberMap.printMap();                     // Output: (nothing, map is empty)
```

---

## 4. Usage Example: String Map
Because the class is generic, the same logic can be reused for **strings**.

```typescript
const stringMap = new MyMap<string>();

stringMap.setItem("name", "Max");
stringMap.setItem("age", "27");

stringMap.printMap(); // Output: name Max, age 27
```

---

## 5. Benefits of the Generic Approach
*   **Type Consistency:** A single map instance can only hold one type (e.g., either numbers or strings), preventing mixed-type objects.
*   **IDE Support:** Because the class is strictly typed, the IDE provides relevant suggestions. For a `stringMap`, you can access string methods like **`.length`** on retrieved items; for a `numberMap`, you can use **math methods**.
*   **Flexibility:** The developer gains the ability to create specialized collections for any data type using a single, manageable class structure.
